# iStCAD v1.0.49.17 — suppress INSERT proxy artifacts

## Evidence
The drawing appears normal in AutoCAD while iStCAD displays large concentric circles/arcs around one selected INSERT (layer `dbao`, handle `172EF7F`). This indicates preview-only geometry generated by iStCAD rather than visible standalone circles in the native drawing.

## Root cause found in source
The v1.0.49.16 adapter still passed some INSERT proxy streams to `ExtractProxyGraphics()`. That method converts every `ProxyCircle` and `ProxyCircularArc` into polylines. A proxy stream is cached display data and is not guaranteed to encode only the active Dynamic Block visibility state. Therefore stale or inactive proxy circles can become visible in iStCAD even though AutoCAD's native evaluator does not show them.

## Fix
- Do not extract proxy geometry for any `Insert`.
- Use native child traversal only when the block has been classified as safe and fully previewable.
- If native traversal is unsafe or unsupported, use the INSERT extents fallback rather than proxy circles/arcs.
- Continue allowing proxy preview for non-INSERT custom entities and dimensions under their existing rules.
- Preserve the original INSERT, its block definition, attributes and proxy data; this is a preview-only change.

## Trade-off and validation
Custom INSERTs that cannot be represented by supported native child entities may show as an extents box instead of a complete symbol. This is intentional to prevent fabricated geometry. Source-level checks and ZIP integrity can be run here; Windows WPF build and rendering against the exact DWG remain required.
